# 野火霸天虎 STM32F407ZGT6 板级接线

## 1. 板卡与通信入口

- [厂家手册] 开发板 MCU 为 STM32F407ZGT6，LQFP144 封装。
- [厂家手册] 板载 USB 转串口芯片为 CH340G。
- [文档设计] 本演示的首个升级通道只使用 USART1，不在本阶段混入 Ethernet、Wi-Fi 或 SPI。
- [开发板实测待补] 需要在实际开发板上确认跳帽、COM 号和收发日志。

## 2. USART1 数据路径

| 数据方向 | 信号路径 |
|---|---|
| 开发板发送到电脑 | `PA9 / USART1_TX -> J12 -> CH340G RXD -> USB -> PC` |
| 电脑发送到开发板 | `PC -> USB -> CH340G TXD -> J11 -> PA10 / USART1_RX` |

- [厂家手册] J11 把 CH340G TXD 接到 PA10/USART1_RX。
- [厂家手册] J12 把 CH340G RXD 接到 PA9/USART1_TX。
- [文档设计] 串口参数为 115200 bit/s、8 个数据位、无校验、1 个停止位、无硬件流控，即 115200 8-N-1。
- [开发板实测待补] 上电前确认 J11、J12 已按板载 USB 转串口方式接通；若拔下跳帽，电脑和 USART1 之间不会形成完整数据通路。

## 3. 二级 Bootloader 与板载 ISP 的区别

- [厂家手册] `BOOT0=0` 时，复位后从内部主 Flash 启动。
- [厂家手册] 板载一键 ISP 会利用 CH340G 的 DTR、RTS 控制 BOOT0 和 NRST，使芯片进入 ST 系统存储器中的 Bootloader。
- [文档设计] 本项目是自编二级 Bootloader：保持 `BOOT0=0`，CPU 先从 `0x08000000` 执行本项目 Bootloader，再决定等待 UART 升级或跳转到 `0x08040000`。

两种方式可以共用 CH340 串口硬件，但启动代码来源不同。板载 ISP 下载成功不能作为本项目二级 IAP 已经跑通的证据。

## 4. 时钟约定

- [厂家手册] 霸天虎板提供 25 MHz HSE 晶振资源。
- [文档设计] 为缩短首次演示链路，本项目起步阶段使用 HSI 16 MHz；只有源码中的时钟初始化确实选择 HSI 时，记录中才可以写“当前使用 HSI 16 MHz”。
- [文档设计] 手册中的 25 MHz HSE 目前只说明板上有该资源，不表示程序已经选择 HSE，也不表示系统已经运行在 168 MHz。
- [开发板实测待补] 若后续切换到 HSE+PLL，需要同步检查 `HSE_VALUE`、PLL 参数、Flash 等待周期、PCLK2 和 USART1 波特率，并用时钟输出或串口误差进行验证。

## 5. CMSIS-DAP 调试连接

- [文档设计] CMSIS-DAP 用于下载 Bootloader、单独下载 APP、查看寄存器和 Memory，不承担 UART 固件传输。
- [文档设计] 调试连接至少需要 SWDIO、SWCLK、GND、目标板电压参考；是否接 NRST 按下载器和板卡接口确定。
- [开发板实测待补] 在 Keil 中选择实际 CMSIS-DAP 探针并确认能识别 STM32F407ZG；仅在工程中存在 Flash 下载算法不代表探针已经连接。
- [开发板实测待补] 首次测试应分别读取 `SCB->VTOR`、MSP、`0x08040000` 和 `0x08040004`，保存截图或调试日志。

## 6. 上电前检查

1. 确认目标芯片丝印或工程器件选择为 STM32F407ZGT6/ZGTx。
2. 确认 BOOT0 保持为 0，避免误入 ST 系统 Bootloader。
3. 确认 J11、J12 接通板载 CH340 与 USART1。
4. 确认电脑识别出 CH340 COM 口，串口工具未被其他程序占用。
5. 确认 Qt/串口工具使用 115200 8-N-1、无流控。
6. 确认 Bootloader 和 APP 使用不同的 IROM1 地址，下载时没有整片擦除或覆盖 Boot 区。
