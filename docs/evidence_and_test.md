# IAP 证据记录与板测清单

## 1. 证据标签

每条结论只能使用与现有证据相符的标签。

- [官方手册] 来自 ST 芯片参考手册、数据手册或 ARM/CMSIS 定义的事实。
- [厂家手册] 来自野火霸天虎板卡资料的接线、器件和示例说明。
- 设计项：本项目选定但尚未由执行结果确认的地址、协议、状态机或测试规则。
- 主机检查：已在电脑程序中运行并保存输入、输出和结果；不能证明 MCU Flash、外设或中断行为。
- [开发板实测待补] 必须在 STM32F407ZGT6 实板完成，目前还没有足够证据。

编译通过、链接通过和源码存在不等于开发板实测通过。串口收到 Boot 日志也不能单独证明固件已正确写入 Flash。

## 2. Current validation notes

| 内容 | 当前标签 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 1 MiB Flash 与扇区 0～11 | [官方手册] | 芯片地址和擦除边界 | 本项目擦写代码正确 |
| CH340、J11/J12、PA9/PA10 | [厂家手册] | 板级 UART 连接方案 | 当前跳帽和实物连接正确 |
| Boot/Param/Run/A/B 五区 | 设计项 | 项目约定和容量计算 | 链接、下载和越界保护已通过 |
| HSI 16 MHz 起步 | 设计项 | 演示阶段的时钟选择 | 当前二进制确实运行在 16 MHz |
| 主机协议及状态机测试 | 主机检查 | 特定测试输入下的软件逻辑 | UART、Flash、复位及真实掉电行为 |
| CMSIS-DAP、UART、Flash、跳转 | [开发板实测待补] | 暂无 | 暂无板级完成结论 |

## 4. 基础板测清单

### B01 CMSIS-DAP 与器件识别

- 操作：连接 CMSIS-DAP，在 Keil 中选择目标探针并读取器件。
- 预期：能识别 STM32F407ZG，并能停止、单步和读内存。
- 保存：Keil Debug/Utilities 配置、器件识别结果。
- 当前状态：[开发板实测待补]

### B02 Bootloader 独立启动

- 操作：仅下载 Bootloader，保持 BOOT0=0 后重新上电。
- 预期：Bootloader 不向二进制协议串口混入文本；在 3 秒窗口内发送合法 HELLO/HOLD 帧能收到正确 ACK。
- 保存：上位机原始十六进制收发日志，并记录 J11/J12 状态。
- 当前状态：[开发板实测待补]

### B03 APP 链接地址与向量表

- 操作：检查 APP `.map`，再把 APP 单独下载到 `0x08040000`。
- 预期：向量表位于 `0x08040000`；地址 `0x08040000` 中保存的是合法初始 MSP，地址 `0x08040004` 中保存的是最低位等于 1 的 Reset Handler。
- 保存：`.map`、`.bin` 长度、Memory 窗口两个向量字。
- 当前状态：[开发板实测待补]

### B04 Bootloader 跳转 APP

- 操作：让升级等待窗口超时或发送启动命令。
- 预期：跳转前 `VTOR=0x08040000`，跳转后 APP 输出自己的独立标识并持续运行。
- 保存：跳转前后的 UART 日志，必要时保存 VTOR、MSP 和 PC 调试值。
- 当前状态：[开发板实测待补]

### B05 正常 UART 升级闭环

- 操作：Qt 或临时串口发送器发送 START、DATA、END，再请求启动。
- 预期：每帧有匹配 ACK；固件先写入非活动槽；整包 CRC32 通过后才进入可搬运状态；Run 区复制后再次校验并启动新版本。
- 保存：上位机日志、Bootloader 日志、镜像长度/CRC、升级前后版本。
- 当前状态：[开发板实测待补]

### B06 A/B 保留策略

- 操作：先建立一个已确认版本，再下载新版本到另一个槽。
- 预期：新 APP 健康确认之前，原已确认槽不被擦除；确认后元数据状态符合设计。
- 保存：升级前后参数记录和两个槽头部内容。
- 当前状态：[开发板实测待补]

### B07 APP 健康确认

- 操作：启动新 APP，让 APP 在完成最小初始化后写入健康确认。
- 预期：Bootloader 下次复位能识别新版本为已确认，不触发回滚。
- 保存：首次启动、确认写入和再次复位日志。
- 当前状态：[开发板实测待补]

## 5. 协议故障注入清单

### F01 帧 CRC16 错误

- 注入：翻转 DATA 帧一个字节但保留原 CRC16。
- 预期：返回 NACK；期望序号和写入偏移不前进；Flash 中不出现该错误数据。
- 当前状态：[开发板实测待补]

### F02 丢包与超时重传

- 注入：丢弃一帧 DATA 或一帧 ACK。
- 预期：发送端超时后有限次数重传；设备不会跳过缺失序号。
- 当前状态：[开发板实测待补]

### F03 重复数据帧

- 注入：同一序号、偏移和内容连续发送两次。
- 预期：设备按幂等规则回复相同进度，不重复推进长度，也不破坏已写数据。
- 当前状态：[开发板实测待补]

### F04 错误序号或偏移

- 注入：发送比期望值大或小的序号/偏移。
- 预期：返回 NACK，并报告设备当前期望值；不得越界写入。
- 当前状态：[开发板实测待补]

### F05 超长固件

- 注入：START 声明长度为 0、超过 256 KiB，或构造 `地址 + 长度` 溢出。
- 预期：在擦除槽位之前拒绝请求。
- 当前状态：[开发板实测待补]

### F06 整包 CRC32 错误

- 注入：所有帧 CRC16 都正确，但 START 中的整包 CRC32 与最终镜像不一致。
- 预期：END 校验失败，不标记为 READY，不搬运到 Run 区。
- 当前状态：[开发板实测待补]

## 6. 启动与掉电故障注入清单

### F07 非法初始 MSP

- 注入：把候选镜像首字改成主 SRAM 范围外或不符合对齐要求的值；若要单独验证向量检查，应同步更新测试镜像的整包 CRC。
- 预期：Bootloader 拒绝跳转并保持可升级状态。
- 当前状态：[开发板实测待补]

### F08 非法 Reset Handler

- 注入：清除 Reset Handler 最低位，或把清除最低位后的地址改到有效 APP 范围外；若要单独验证向量检查，应同步更新测试镜像的整包 CRC。
- 预期：Bootloader 拒绝跳转，不执行未知地址。
- 当前状态：[开发板实测待补]

### F09 下载过程中断电

- 注入：在擦除槽后、若干 DATA 帧后分别断电。
- 预期：重新上电后把该槽识别为未完成；原 Run 区和已确认槽仍可使用；可以重新开始下载。
- 当前状态：[开发板实测待补]

### F10 搬运 Run 区时断电

- 注入：在擦除 Run 后、复制一部分后、复制结束但未写状态时分别断电。
- 预期：重新上电不跳转到半成品 Run；从仍完整的 A/B 源槽重新搬运并校验。
- 当前状态：[开发板实测待补]

### F11 新 APP 未确认复位

- 注入：让新 APP 在健康确认前复位、看门狗复位或故意进入异常。
- 预期：Bootloader 根据 PENDING 状态和尝试次数恢复已确认旧镜像，不无限启动坏版本。
- 当前状态：[开发板实测待补]

### F12 UART 物理断开

- 注入：断开 J11 或 J12，或关闭电脑串口。
- 预期：Bootloader 不误写 Flash；等待窗口超时后按当前有效镜像策略启动或继续安全等待。
- 当前状态：[开发板实测待补]

### F13 参数区写满和擦除中断

- 注入：把 Param 追加区写满，并在扇区压缩或擦除阶段断电。
- 预期：只有实现了额外备份机制后才能要求自动恢复。
- 当前设计限制：五区占满全部扇区，没有参数备用扇区；此项在补充安全方案前应记录为“阻塞”而不是伪造通过结果。
- 当前状态：[开发板实测待补]

## 7. 最小验收门槛

只有同时保存以下实板证据，才可以把串口 IAP 主链路标记为开发板实测通过：

1. Bootloader 上电启动和 USART1 双向通信。
2. APP `.map`、两个向量字、VTOR/MSP/PC 与 `0x08040000` 链接关系一致。
3. 一个正常固件完成“接收、槽内 CRC、搬运、Run 区 CRC、启动、健康确认”。
4. CRC16 错帧、重复帧、丢包重传和整包 CRC32 错误均未造成错误写入或错误启动。
5. 下载中断电和搬运中断电均能恢复到定义的安全状态。
6. 新 APP 未确认时能恢复已确认版本。

目前这些项目仍有开发板检查待补。后续每通过一项，应填写实际结果和适用范围。
